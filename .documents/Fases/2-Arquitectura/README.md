# Fase 2: Arquitectura y Requisitos

## 🎯 Objetivo de la Fase
Transformar la idea de negocio en definiciones técnicas concretas. Aquí se decide **cómo** se construirá el sistema y se documentan los requisitos funcionales y no funcionales.

## 🔑 Conceptos Clave

### 1. Product Requirement Document (PRD)
Es la "biblia" del producto. Describe:
*   **Funcionalidades (Features):** Qué debe hacer el sistema.
*   **User Personas:** Perfiles de usuario.
*   **Requisitos No Funcionales (NFRs):** Rendimiento, Seguridad, Escalabilidad.

### 2. Arquitectura de Software
*   **Stack Tecnológico:** Lenguajes, Frameworks, Bases de Datos.
*   **Diagramas C4:** Visualización de alto nivel (Contexto, Contenedores, Componentes, Código).
*   **Decisiones de Arquitectura (ADRs):** Justificación de por qué elegimos una tecnología sobre otra.

## 🛠️ Herramientas Utilizadas
*   **Prompts de IA:** `prd-generator.md`, `architecture-design.md`.
*   **Sintaxis Mermaid:** Código que la IA generará dentro de los documentos Markdown para visualizar diagramas automáticamente en GitHub y VS Code.

## 📝 Entregables Esperados
Al finalizar esta fase, tendrás en tu carpeta `.context/architecture/`:
1.  Un **PRD** detallado.
2.  Un documento de **Diseño del Sistema** con diagramas y stack tecnológico.
